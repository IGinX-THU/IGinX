## 已确认的设计语义与实现差异

1. IGT-18 的 `SELECT * FROM *.c0` 按现有 SQL 路径语义不表示设计中的叶路径通配。经用户确认，测试采用等价的 `SELECT c0 FROM *`，同时保留 `queryData(["*.c0"])`。90 列中的 58 个保留列和 32 个可见列、分页、计数、聚合均实际断言，不将空结果视为通过。
2. jetcd 0.5.11 在全局认证关闭时使用凭据会失败。因此 IGT-50 按设计允许的维护窗口执行三节点上线和回退。权限必须覆盖实际字节前缀（例如 `/userroot`），不是仅覆盖 `/user/`。
3. REST 注解写入要求 Write。安全模式使用可由 LONG/DOUBLE 精确表示的集群唯一引用，避免为分配注解编号而隐式读取共享计数器；LONG、DOUBLE、BINARY 的正例和注解内容读回均覆盖。旧模式保留原计数器行为。
4. IGT-33 在撤销与写入同时发生时区分成功确认、入口拒绝和已进入执行的取消响应。所有成功确认行必须存在，入口拒绝行不得存在；取消时正在执行的行允许提交或未提交，但完整读回在主存储失效前后必须一致。
5. IGT-24/27 使用同一个测试编排真实的改密、停进程、重启、验证、恢复和再次重启，等价覆盖三阶段过程；测试不依赖运行顺序或操作者部署。
